它不是改写按钮，是一间 AI 编辑室。

回声编辑部把短视频素材变成可判断、可改写、可审稿、可包装、可复盘的内容资产。当前能力已经跑通“提取、转写、改写、配音、成片”，下一步是把管道升级成编辑工作流。

暂停手抄有价值的视频，整理起来很慢。
平台改写抖音口播不会自动变成小红书笔记。
审稿缺位生成一版就结束，没有评分和修改。
包装断层文案、配音、字幕、视频散在不同工具。
回响丢失发布后的数据没有反哺下一次创作。

编辑部的核心，是判断与分工。

长期看，回声编辑部不应该只有“小红书 / 抖音精选”两个按钮，而应该有多角色 AI 编辑：先判断素材，再出初稿，再审稿修改，最后做发布包装。

Topic 选题编辑

判断这个视频值不值得做，适合哪个平台，从哪个角度切入。

Draft 初稿编辑

根据风格模板生成第一版稿件，保留原内容的事实和情绪。

Review 审稿编辑

给标题、开头、结构、口语感打分，提出修改建议。

Package 包装编辑

准备配音、字幕、封面、配图和竖屏视频，进入发布状态。

最终沉淀三类资产：稿、声、片。

短视频不是被搬运，而是被重新编辑。每一次生成都应该留下稿件、声音、视频，以及可复用的方法论。

稿 / Draft

平台文案、标题、标签、口播稿、风格模板和审稿建议。

声 / Voice

TTS（文字转语音）生成中文旁白，支持语速和声音风格。

片 / Cut

配图、字幕、音频和 1080x1920 竖屏视频，形成最小成片闭环。

本地启动，一条链接开始。

先配置 DeepSeek API Key。Pexels API Key 可选，只在生成带配图视频时需要。

git clone https://github.com/Rookage/echo-editorial.git
cd echo-editorial

npm install
pip install edge-tts faster-whisper

cp .env.example .env
npm start

# open http://localhost:3000

好工具要知道自己的边界。
